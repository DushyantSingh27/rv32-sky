## Stage 0 — what Verilator 5.050 does with coverage data (`27fa18f`)

Measured on `verif/verilator/cov_semantics/`, a three-file probe. None of this is
in `--help`. All T1, 2026-10-12.

| # | Measurement | Consequence |
|---|---|---|
| T1 | a second run **overwrites** `coverage.dat` | every run writes its own file; an explicit merge is required |
| T2 | `verilator_coverage --write` merges as a union, counts summed | merging is safe; hits are additive |
| T3 | points are keyed by **instance path** — the same file under two tops gives two point sets | the per-file union across instances is computed after the merge (`covdat.py build_union`, which first asserts the key is unique within an instance) |
| T4 | toggle coverage **silently drops** every signal over 256 total bits, packed structs and unpacked arrays included (`w257`, `w1024`, `w4096`, `ws`, `arr64`, `arr2k` all ABSENT); `--coverage-max-width` restores them | the width has to be chosen and measured, not left at default (step 6) |
| T5 | toggle points are directional: two per bit | the toggle denominator is 2 × bits |
| T5c | `--write-info` folds toggle points into lcov branch records | lcov output is not used for any number here |
| T6 | a `.vlt` `coverage_off -lines` removes exactly the points in range: logic by line, toggles by declaration line | the exclusion file can be generated (step 5) |

`tools/guards.mk` pins Verilator and `verilator_coverage` to the same directory and
revision. Shown to fire with the OSS CAD Suite first on PATH, matched on the

## Stage 1 — one command for every number

Step 1 was read-only (the harness sources, the coverage API, the build files);
steps 2 to 7 are named in their commit messages.

- **Steps 2-4 (`1d947bb`): the harnesses wrote no coverage.** Built with
  `--coverage-*`, each ran, passed, and left no file. `harness_cov.h` gives all
  three one `finish()` that writes before the model is deleted, refuses both wrong
  configurations, and checks the file is non-empty. `--cov-file` is parsed from the
  harness's own argv because `tb_act4` rebuilds argv for Verilated: a plusarg would
  have been dropped and all 47 ACT4 runs would have written one default file, 20 at
  a time. A nested `obj_dir/cov` layout made Verilator's generated makefile link the
  *normal* build's harness object (`VM_COVERAGE=0`) into the coverage binary; the
  harness's own check caught it, the layout is now a sibling `obj_dir_cov`, and the
  recipe asserts the object was compiled in its own directory.
- **Step 5 (`ea23a3b`): stage 0 decision A — a line is excluded from coverage exactly when
  it is excluded from synthesis.** `gen_cov_vlt.py` evaluates every line twice,
  `SYNTHESIS` undefined and defined, and emits a `coverage_off` range for each run of
  lines compiled only in the first. Eight ranges today (five assertion blocks, the
  trace ports and logic in `rv32_core`, the TCM loader), regenerated on every build.
  17 self-test cases, 6 of them refusals.
- **Step 6 (`6b5192c` and a measurement run): the toggle width is 8192.** Three
  builds of the core harness, default / 8192 / 1,048,576, run on `t01`:
  - the default drops **1,984** `rtl/core` toggle points, all of them
    `regfile.sv` `regs` — the 992-bit register array, the largest block in the design;
  - 8192 and 1,048,576 give **identical** `rtl/core` toggle sets
    (`a_only=0 b_only=0 unpaired=0`);
  - only 1,048,576 instruments the TCM array `mem` (131,072 points) — `rtl/mem`,
    reported only.

  8192 is the smallest of the three that measures every `rtl/core` bit.
- **Step 7 (`a68a279`): `run_coverage.sh`.** Builds the three coverage harnesses
  (guarded, with the generated exclusion file), runs the regression set — the
  lockstep programs with their expected checksums, the 47 ACT4 tests in parallel,
  the decoder harness — each into its own file, **merges passing runs only**
  (stage 1 decision D: a failing run may have reached lines through wrong behaviour),
  asserts the number merged, and reports `rtl/core` against §5.3. Every input is
  read from where it already lives and asserted. `probe_traps.S` is deliberately
  outside the set. Baseline: 54 runs, 3 s.

**Decisions.** Two plans each had decisions labelled A to D, so each is named by
plan here. Read back from the planning record on 2026-10-26; until this file, none
of the reasoning was committed anywhere, and the code labels (`gen_cov_vlt.py`
"decision A", `run_coverage.sh` "decision B" and "decision D") pointed at nothing.

*Stage 0 plan, approved 2026-10-09:*
- **A — debug logic is outside the coverage scope.** The trace ports and
  assertion blocks under `` `ifndef SYNTHESIS `` never become gates, so the
  denominator is the synthesizable design, which is what §5.3's "on `rtl/core`"
  means. Implemented by generating the exclusions (step 5), not hand-written
  pragmas.
- **B — the gate covers `rtl/core` only.** `rtl/mem` (`tcm.sv`, a memory) is
  reported but not gated; `rtl/pkg` (mostly types) is not reported.
- **C — ACT4 is instrumented.** Leaving its 47 tests out would overstate how much
  of the uncovered remainder is genuinely unreachable.

*Stage 1 plan, approved 2026-10-12:*
- **A — env 7 is not in the coverage set.** It runs the same t02-t06 images on
  the same RTL as the core harness, so it adds no stimulus, at the cost of an
  instrumented UVM build.
- **B — the TCM array stays out of toggle by the width limit.** At 8192 the
  array `mem` is the only `tcm.sv` signal dropped (step 6, S6b), and `tcm.sv` keeps
  its line and branch points; a whole-file exclusion would have lost those.
- **C — ACT4 coverage runs loop over the 47 built ELFs directly**, with
  `run_tests.py`'s pass rule, rather than through a second ACT4 core config.
- **D — only passing runs are merged.**

### Reset-twice (`82442ac`)

Verilator starts every flop at zero, so a flop whose reset is missing **and** whose
reset value is zero passes every run that resets once. `tb_core --reset-at N`
asserts a second reset mid-run; PASS requires the post-reset run to begin with the
pre-reset one exactly. `run_coverage.sh` runs `t07_counters --reset-at 60`,
requiring the pre-reset run to reach t07's trap handler.

| Mutant | Reset turned into hold | Ordinary t07 under lockstep | `--reset-at 60` |
|---|---|---|---|
| R1 | `minstret_q` | **agrees**, 104 instructions | FAIL: retirement 4, `x5` `0x04` vs `0x1e` |
| R2 | `pc_q` | **agrees** | FAIL: retirement 0, PC `0x00` vs `0xb4` |
| R3 | `id_ex_q` | **agrees** | FAIL: retirement 0, PC `0x00` vs `0xac` |

All three pass lockstep against Sail — the blind spot this mode exists for, predicted
before the run — and all three fail reset-twice.

### Decoder legality (`1c6ba1b`)

For **all 2³² instruction words** — the decoder is combinational and the word is a
free input, so the proof is complete — the decoder never emits `alu_op` above
`ALU_PASS_B`, `branch_op` 7, `mem_size` 2'b11 or `wb_sel` 2'b11. Fields are checked
by name through `ctrl_t`.

| Job | Status |
|---|---|
| prove, committed decoder | `PASS 0 0`, k-induction |
| cover: `ALU_PASS_B`, `BR_GEU`, `MEM_W`, `WB_PC4` each reached | `PASS 0 0`, all four at step 0 |
| MA: LUI emits `alu_op` 11 | `FAIL 2 0`, on its own assertion only |
| MB: BGEU emits `branch_op` 7 | `FAIL 2 0`, own assertion only |
| MS: LHU emits `mem_size` 2'b11 | `FAIL 2 0`, own assertion only |
| MW: JAL emits `wb_sel` 2'b11 | `FAIL 2 0`, own assertion only |

This is the **decoder half** of the argument that six of the twelve lines below are
unreachable. The **pipeline half** — those fields reach the ALU, LSU and WB mux only
as the decoder's output, as zero (reset, flush, stall bubble), or as that output with
`reg_write`, `mem_read`, `mem_write` cleared (`rv32_core.sv` 259-279, 647-650,
742-749, 780-784) — **is a reading of the code, not a proof.**

**Why `pc_prove` does not close — measured, and my prediction was half wrong.**
I predicted the induction step would start from `mtvec_q[1]=1`. The counterexample
(`trace_induct.vcd`, 21 steps) holds `u_csr.mtvec_q = 0xfffffffd` from step 0 and
never writes it — bits [1:0] = **01**, so bit 0, not bit 1. `mepc_q` starts aligned.
The PC stays aligned for steps 0-19; at step 18 an illegal instruction (`0xffffffff`)
traps with cause 2, `redirect_pc` becomes `0xfffffffd` at 19, and `imem_addr`
follows at 20. That state is unreachable from reset — every write masks the bits —
but induction is not told so. Closing it needs `mtvec_q[1:0]==0` and probably
`mepc_q` and `redirect_pc` invariants, which `csr.sv:248` and `if_stage.sv:79-84`
already state under `` `ifndef SYNTHESIS ``, where slang does not see them.
**Logged as a follow-up, not done.**

### The twelve lines (`0b13c77`)

Each was a `default:` no legal input reaches. SystemVerilog cannot put `default` in
a case item with a value, so each fold **removes one legal arm and lets `default`
carry its behaviour**; every `case` keeps a `default` (PROJECT_INSTRUCTIONS 4.2).
The thirteen edits are defined once, in `verif/formal/fold_equiv/folds.py`.

| Class | Lines | Fold | Behaviour change |
|---|---|---|---|
| A — every selector value had an arm | `decoder` 90, 119; `lsu` 71; `regfile` 103, 115 | last arm → `default` | none, any input |
| B — unreachable from the enclosing arm | `decoder` 295 (`funct3[1:0]==00` is taken by the arms for 000 and 100) | `CSR_RC` → `default` | none, any input |
| C — `default` already did what one arm did | `alu` 58 (`BR_NONE`); `lsu` 59, 83 (`MEM_W`); `rv32_core` 890 (`WB_ALU`) | that arm → `default` | none, any input |
| D — `default` differed from every arm | `alu` 45 → `ALU_PASS_B`; `lsu` 50 → `MEM_W` (so all three `lsu` size cases treat 2'b11 as a word) | chosen arm → `default` | only for `alu_op` 11-15 / `mem_size` 2'b11 |

**Evidence** (`run_fold_equiv.sh 94f8e74`, 2026-10-26, 17 of 17 as predicted):

| Check | Method | Result |
|---|---|---|
| `id_rf` regfile vs itself (control: the flow closes on state) | Yosys equiv | 1,057 / 1,057 `$equiv` cells proved |
| `dec` D90 D119 D295 | Yosys equiv, all inputs | 69 / 69 |
| `lsu_c` L59 L71 L83 | Yosys equiv, all inputs | 95 / 95 |

`equiv_simple -seq 5` proved every cell; `equiv_induct` found none left. Per
`help equiv_induct` (read 2026-10-25, T2) its equivalence is the weak kind — the
circuits "will not diverge after they produce equal outputs … for at least N
cycles" — which is sound here: gold and gate come from the same text, reset
identically, and every passing check has a wrong fold that fails it.

**What the class-D folds rest on:** the decoder-legality proof (complete) and the
pipeline reading above (not a proof). If that reading were wrong, an out-of-range
encoding would reach the unit — and then old and new behaviour would be two
different arbitrary answers to an impossible input.

## The 722 uncovered toggle points

§5.3 decision, M3.7 stage 2: unreachable toggle points stay **in** the denominator.
The number is reported as measured, and every point it misses is accounted for.
`classify_toggles.py` does the accounting: it reads `merged.dat`, takes the same
union the gate takes, and matches every uncovered `rtl/core` toggle point against a
rule naming its class and source line. It **exits 1** if a point matches no rule or
two, or if a rule matches nothing — so a new uncovered point cannot go unexplained,
and a rule whose reason has gone away cannot linger. Both failure paths were shown
to fire (one rule removed → 2 UNMATCHED; a rule for a covered point → STALE).

The 12 PC-carrying signals: `if_stage` `pc`, `if_id.pc`, `pc_d`, `pc_plus4`,
`pc_q`; `rv32_core` `imem_addr`, `if_id.pc`, `id_ex_q.pc`, `ex_mem_q.pc`,
`mem_wb_q.pc_plus4`, `if_pc`; `csr` `trap_epc`.

**By basis:** construction 282, stimulus 312, tied 74, bounded 52, proved 2.
**410 of 722 points cannot toggle in this RTL; 312 can and are not exercised.**
With `PC_HIGH` exercised, toggle would read 8,562 / 8,972 = 95.4%. It is not
excluded to get there: those bits are real hardware.

`PC_HIGH` is the one stimulus gap, and it is not unchecked behaviour: riscv-formal
and `core_props` run with unconstrained instruction memory, where a JALR can take
the PC anywhere (T4 — that the solver actually visits high PCs in those checks is
not measured). A lockstep program that jumps above 512 KB would close it.

**The 2026-10-17 classification is lost.** It classified 610 points at the
baseline into a scratch file that did not survive a workspace rebuild, and was never
committed. It is superseded by this one, which is regenerated from committed code.
The loss is the reason the TSV and its generator are committed this time.

  assertions to the solver** (K6/K7).
- **Verilator zero-initialises flops**, so a missing reset whose reset value is zero
  is invisible to a single-reset run (R1-R3 above).
- **Undriven pipeline-register bits.** In the whole-core equiv jobs Yosys reports
  "Setting undriven nets to undef" for `ex_mem_q` [75:64], [94:84], [110:100] and
  `mem_wb_q` [107:96], [126:111], [142:132], identically on both sides. Likely
  `ctrl` fields nothing reads after EX, removed with their flops (**T4, not
  checked**). Does not affect equivalence; may matter for area.
