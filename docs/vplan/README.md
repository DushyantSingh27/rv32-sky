# Verification Plan — RV32-SKY

**Created:** 2026-08-13
**Scope:** full RV32IMC_Zicsr, including features whose RTL does not yet exist.
**Status:** living document. Update whenever an environment or a feature changes.

## What this is

A feature-to-coverage traceability matrix. Every feature of the target ISA and
every microarchitectural mechanism in `PROJECT_CONTEXT.md` §3 appears here
exactly once, with an explicit verification status.

PROJECT_INSTRUCTIONS §5.3 requires this as an M2 deliverable, "not an
afterthought". It is written **prospectively** — features enumerated from the
RISC-V specification and from this project's own design decisions, then mapped
to coverage — rather than retrospectively from the bins that happen to exist.
The difference matters: a retrospective plan can only report what was covered,
never find what was missed.

## How to read a row

| Column | Meaning |
|---|---|
| **Feature** | One testable behaviour |
| **Source** | Spec section, or the project decision that defines it |
| **Method** | How it is verified: UVM, RAL, formal, compliance, directed |
| **Env** | Which environment, or the milestone that will own it |
| **Coverage** | Coverpoint or cross name, with bin count |
| **Status** | See below |
| **Mut** | Whether a checker for this was demonstrated to FAIL on an injected fault |

## Status values

| Status | Meaning |
|---|---|
| **Covered** | Bin exists and closed at 100% |
| **Partial** | Bin exists but incompletely exercised, or covered indirectly |
| **Planned** | Environment exists, this bin does not |
| **Deferred** | RTL does not exist yet — owned by a later milestone |
| **Waived** | Deliberately out of scope, with a recorded reason |

## The "Mut" column

Non-standard, and included because it earned its place. Mutation testing
(`docs/results/0011`) found that env 3 reported zero mismatches and 100%
coverage while being **unable to detect** a fault in the behaviour it claimed to
verify. Coverage measures what was exercised; it says nothing about whether the
checking works.

- **Y** — a fault in this behaviour was injected and the environment failed
- **—** — not individually mutation-tested
- **N** — tested and the fault SURVIVED (a known hole)

## Provenance of the numbers

**Structure** — which coverpoints and crosses exist, and their exclusions — is
extracted from the source by `tools/extract_coverage.py`, which self-checks its
output against counts recorded from real coverage reports and fails loudly on
disagreement.

**Bin counts and closure percentages** come from DSim `dcreport` output,
recorded in `docs/results/0004`, `0005`, `0008` and `0010`. They are NOT
generated by the extraction script: four revisions of its bin-counting logic
each produced a plausible but wrong number, and it was removed rather than
trusted. See the note at the top of that file.
